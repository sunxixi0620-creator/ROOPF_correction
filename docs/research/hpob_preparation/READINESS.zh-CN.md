# HPO-B 接入前的源码审查

固定官方代码提交：`f16c0c52c27ba4e928dd3ad648231726cb06a9ab`。来源和四个文件哈希见 [SOURCE.json](SOURCE.json)。仅下载 README、许可、handler 和示例代码，没有下载任何训练/验证/测试响应表，也没有运行新的 HPO 目标评估。固定来源并不等于任务划分和实验协议已经全部完成。

源码审查发现三个需要明确处理的接口约定：

1. `load_data` 无论 `only_test` 是否为真，都会先读取 meta-test 响应表。官方 mode=`v3` 因此会把训练、验证、测试响应同时装入对象。仅加载并不自动构成训练泄漏，但我们的训练/开发进程应只打开其获准的 split 文件，不能用这一默认对象作为隔离边界。
2. 离散 `evaluate` 用整个目标响应表的最小/最大值归一化，再把归一化后的已观测响应传给方法。这是该实现的基准约定；若采用“算法只能知道已付费响应”的严格实验合同，应传原始已观测值，或仅用已付费样本确定的变换。完整表的归一化遗憾只由评估器计算，不能送进优化器。
3. `n_trials` 不含初始化；代码检测到已命中全表最大值后提前结束，再补齐历史曲线。我们的实际调用账应明确初始化也计费，不能把补齐后的曲线长度当真实执行的调用数。若保留固定预算轨迹，也不能让优化器通过未知最优值决定停止。

后续接入合同：

- 保留官方 v3 的源/验证/确认角色，先按输入类型、维数和预算可行性冻结纳入规则，再读开发成绩。
- 先接离散模式，向算法只给已观测 `(X,y)` 和未评估候选 `X`；不传待评估响应、全表极值或最优配置。
- 每个方法使用相同初始化与真实查询账；共享基线不复制为独立运行。
- 训练 loader 只读源文件；验证 loader 只读开发文件；确认标签交给单独评估器，协议冻结前不打开。
- 核对跨搜索空间的原始数据集身份；“同搜索空间迁移”和“未见数据集迁移”的隔离要求分别写清。
- 官方目标是最大化 accuracy；当前 ROOPF 最小化约定需要在入口明确转换，不能在汇总时临时改符号。
- 尚未确定具体任务 ID 和完成成熟方法复现，因此不能宣称外部验证已经启动或通过。
