# 公开控制仿真任务检索与接入建议（2026-09-30）

结论：已有公开、可追溯的控制仿真路线，无需以私人硬件数据作为研究前提。推荐把下一阶段限定为一个具有物理参数变化的控制器调参任务族，先验证迁移与在线适应，再考虑UAV扩展。下列选择基于任务定义和接入条件，不基于ROOPF在任务上的成绩；本轮没有运行ROOPF或进行模型筛选。

## 1. MetaBO的Furuta旋转倒立摆：优先的迁移机制任务

[官方代码](https://github.com/boschresearch/MetaBO) · [原始论文](https://arxiv.org/abs/1904.02642) · [官方Furuta训练配置](https://github.com/boschresearch/MetaBO/blob/master/train_metabo_furuta.py)

论文研究从相关任务学习采集函数，并包含Furuta仿真到硬件的实验。我们使用仿真只能声称仿真结果，不能承接作者的硬件结论。官方配置直接提供4维控制器参数，以及臂/摆质量、长度的变化：名义参数0.095、0.024、0.085、0.129，训练范围分别乘0.75到1.25。控制器域为[-0.5,0.2]、[-1.6,4.0]、[-0.1,0.04]、[-0.04,0.1]。这些都是上游基准定义，不是我们按效果选出的设置。

适合之处是源与目标之间有明确物理联系，在线适应有可解释对象。可先从该配置确定任务分布与源/开发/确认划分，保留所有失败/发散试验。MetaBO也应列为相关方法及可复现时的迁移基线，不能仅借任务而忽略已有方法。

状态：已核对论文和官方配置；本机GitHub HTTPS下载与SSH克隆遇到连接重置，尚未跑通Furuta。仓库已归档，许可证AGPL-3.0；后续固定上游提交、单独保存依赖环境，不能把“有代码”写成本机已复现。

## 2. TuneControl：轻量控制调参接口与近期基准候选

[官方仓库](https://github.com/Data-Science-in-Mechanical-Engineering/tunecontrol) · [官方发布包](https://pypi.org/project/tunecontrol/0.1.0/) · [2026综述与基准论文](https://arxiv.org/abs/2609.09403)

0.1.0发布于2026-09-12，MIT许可，官方要求Python3.12。CartPole有1–4个状态反馈增益及MAE/LQR/ITAE目标；串联水箱有2个PI增益及SSE/LogSSE/二次/上升时间/超调目标。支持确定性和噪声配置，返回标量代价和状态、输入、时间、单位等轨迹字段。非有限目标以NaN及诊断返回，不能默默丢弃失败查询。24/10种标准配置是维度/目标/噪声组合，不是24/10个独立物理任务族。

发布包源码中，水箱Dynamics暴露k1..k4、时间步长和初态，适合进一步核查任务参数化；CartPole公开Config主要是维度/目标/噪声，不能假定已经提供与Furuta相同的质量/长度接口。变化范围仍须取自物理模型依据并在测试前冻结，不在看结果后改范围。

本机实际完成7次最小调用：确定性CartPole两次、确定性水箱两次、带噪CartPole连续两次与重置种子重放一次。确定性重复和噪声重放均一致。CartPole默认2维域中点[-40,-6.25]的MAE为8.273368，与官方示例8.2734一致。CartPole调用约0.17–0.19秒，水箱约0.011–0.013秒；这些是本机少量CPU串行接口检查，不是系统计时基准，也不能称昂贵仿真。

重要环境边界：上述调用是把未修改的纯Python wheel按路径加载至现有Python3.10中完成的探索性兼容检查，**未完成官方支持的Python3.12环境复现**。没有向原实验环境安装或降级依赖。正式实验前须建立独立3.12环境、锁定版本并重新核验。发布包SHA256与PyPI记录一致，保留原MIT许可。[调用记录](TUNECONTROL_SMOKE.json)。

## 3. safe-control-gym：后续UAV动力学扩展

[官方仓库](https://github.com/learnsyslab/safe-control-gym) · [2022论文](https://doi.org/10.1109/LRA.2022.3196132)

官方提供PyBullet倒立摆与四旋翼、CasADi符号动力学、约束、输入/参数/动力学扰动。与现有二维路径软惩罚不同，能用于闭环动力学下的控制调参和鲁棒性评估。项目不是已经定义好的ROOPF调参协议：仍需固定控制器类型、增益范围、场景、目标、失败处理及运行预算。仿真成功不等于真实飞行或算法安全保证。本轮仅完成文档核查，未安装或运行此项目。

## 未优先采用的候选

[LegOpt](https://github.com/martimbrandao/legopt-benchmark)有机器人姿态/轨迹优化与约束，但官方现有说明要求Python2.7和OpenRAVE，接入成本较高；先不投入迁移。机器人推物/rover类基准也有文献来源，但本轮没有完成其原始实现核验，不将第三方封装当作已验证的一手实现。

## 下一步的具体执行建议

1. 优先完成Furuta原始仿真入口复现；TuneControl保留为已完成初步接口检查的备选，不同时大规模训练多条线。若原始代码仍无法获取，先完成TuneControl3.12环境，候选切换按可复现性记录，而不是按ROOPF胜负选择。
2. 从上游物理参数定义构建源/开发/确认任务。先完成固定种子、重放、失败计数和真实调用时间检查。机器参数与真实模型可用于生成/审查任务，但优化器是否可见这些信息必须事前固定，各方法一致。
3. 没有实际工程绝对容差时，使用上游代价、完整预定预算曲线和失稳/约束事件作为主指标，不再编一个“距表最优0.05”的通用达标标准。未知真实最优不能报成可计算的真遗憾。若需要达标时间，目标应来源于上游规范或冻结的开发参考，不能使用确认集后验最优。
4. A=同一离线策略；O=结构匹配纯在线；F=融合；FR=含residual融合。另加Sobol、CMA-ES、GP-EI及适用的迁移基线。完整比较之前必须先确定4维模型身份；原10维checkpoint不能靠填充或截断就宣称直接适用，应用适配/重训须单独归档。
5. 先验证F相对A与O的两方向增益，再验证FR−F。无法通过则缩小贡献，不按任务更换开关。4维或2维任务不能解决原论文中高维扩展证据不足的问题。

资源安排：仿真与数据采集优先CPU进程并行，每进程限制BLAS线程；只有后续神经网络训练/批量推理适合GPU。现有7次试跑不足以估计整轮重训时间；正式计划应由单任务实测成本和冻结任务数量计算。
