# 本轮要解决的问题和执行入口

本轮检验：在原始数据集隔离、同一搜索空间的真实HPO任务中，源任务信息
是否能帮助强在线GP更快达到较好结果。先跑成熟迁移与简单先验参照，
再根据预定条件决定是否训练神经先验。它属于方法重设计的开发证据，
不归入原解锁版或原residual的有效性证明。

四组固定为O（纯在线）、P（只用静态源均值）、A（固定源均值＋在线GP）、
R（2022 bootstrap形式的RGPE-TAF/Matern重实现）。它们不是原论文旧的
四个模块命名。共同初始5点、总预算105、66任务×5种子，共1320条、
138600次目标表查询。源库344任务、固定86573条历史记录；确认集查询0。

进入神经训练的条件在HPOB_TRANSFER_DEVELOPMENT_V1.md预先写明：R对O
在第5～40次的平均标准化regret至少减少0.01，且校正区间支持改善；
终局退化的校正上界不超过0.01。R对A/P的比较用于辨别复杂迁移机制
以及在线适应的增量。即使通过，这也仅表示值得开展神经先验研究。

执行顺序：冻结→16个CPU工作进程拟合源GP→2个GPU工作进程预计算
源预测→全66缓存的CPU独立重放→16个CPU工作进程跑四组→完整汇总。
每个工作进程的BLAS/PyTorch线程数为1。选择GPU缓存经过人工数据的
CPU/GPU精度检查；所有真实缓存还要在目标查询前单独通过重放。

后台入口：`.venv/bin/python -u scripts/run_hpob_transfer_pipeline_v1.py`。
进程ID在results/hpob_transfer_development_v1/pipeline.pid；阶段日志是
pipeline.log、sources.log、caches.log、cache_audit.log、run.log、report.log。
任何阶段失败就停止后续阶段。源模型/缓存/完成轨迹有内容哈希，目标
查询先写持久记录，支持恢复；不能删除查询记录后当作从未调用过。

完整结论自动写入本目录RESULTS.json和CONCLUSIONS.zh-CN.md；在文件
生成前不能把部分任务进度当作科学结论。本轮未设置自动训练新神经网络，
因为神经训练目标和架构应由这次完整结果及源任务诊断共同决定。

工程预备代被保留在results/hpob_transfer_preflight_v1，包含344个源拟合
和66个源缓存，目标调用0。在首个目标查询前补齐了“TAF处处为0”的
合法并列处理，重新冻结；使用相同源行，没有增加独特历史标签数量。
两次源拟合/缓存的实际成本必须分别保留。不是根据目标结果修改方法。
