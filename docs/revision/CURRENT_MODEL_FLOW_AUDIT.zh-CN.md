# 当前模型与完整实验流程审查

审查基线：`8712fd1`，最终10-D方法为已选定的解锁配置。本次检查源码、构造入口、训练日志和完成后的实验协议，没有修改优化规则、权重或重跑基准。原始训练命令/种子仍未完整恢复；以下严格区分历史证据与本轮受控重训。

## 能否通过修改达到论文预期

有明确可检验的改进方向，但不能保证得到原稿的总体领先或可靠性效果。修复入口和实现一致性可以提高可复现性；更换训练目标、评分或门控会产生新方法候选，必须在开发集上选择、冻结后另行测试。已查看的COCO实例101/102和当前CEC2017结果，不能继续被当作下一轮完全未查看的测试集。

## 1. 数据与离线训练

1. Claude生成器提供36个函数、12类景观及参数/偏移生成接口；这不是LLM在线参与优化。恢复出的审计前后模块成员相同、顺序不同，审计还补入10个低于阈值的函数。BBOB/CEC景观信息曾参与开发/审计，不能声称全流程独立。
2. 先训练anchor。当前结构是适应度/秩注意力、坐标投影和解码器，从已排序种群产生两个候选；共有36,534个参数。原10-D权重被冻结使用。受控重训使用80epochs、36函数、每函数64条轨迹、种群100、每轨迹300主NFE、Adam0.001、4函数梯度累积；按训练损失保存模型。该配方不等于已经找回原权重的完整历史运行。
3. 冻结anchor，在生成训练函数上运行候选生成/搜索，额外评估候选池以制作标签。新20-D标注的行为策略明确为无residual的完整搜索。全池教师真值只用于离线日志，不用于正常在线候选筛选。一个300NFE轨迹有100轮，池36点加两个anchor产生每轮38个教师求值。
4. 用日志训练residual：原10-D为27维特征、128隐藏宽度、20,481参数MLP，标签为`improved_best`，正类加权BCE；1.2M抽样行按函数ID拆分训练/验证。七个函数仅对residual留出，anchor使用同一36函数集。按留出排序指标等组合选择checkpoint，而非测试优化成绩。训练后冻结。

依赖关系：`生成函数 → anchor → 全池日志 → residual`。在线proxy不在这个离线训练链中；它在每个新任务上重新拟合。

## 2. 最终在线模型中哪些部分训练了

| 模块 | 实际来源/更新 |
|---|---|
| anchor | 加载训练checkpoint；测试时不更新网络权重 |
| residual | 加载训练checkpoint；测试时不更新网络权重 |
| 五成员ridge proxy | 使用当前任务的已付费archive重新拟合；无跨测试任务共享观测 |
| 状态编码器、neural portfolio、operator gate | 固定种子初始化，没有加载额外训练checkpoint；不是已完成端到端训练的融合网络 |
| 算子成功记忆 | 按被评估候选的真实效果作规则更新，不是网络反向传播 |

六算子为neural elite、current-to-pbest、covariance elite、trust region、coordinate pattern、opposition restart，各6个候选槽位。池中的neural模块与已经训练的anchor是两个不同对象。

## 3. 一次300NFE测试轨迹

1. 按固定实例与种子采样100点，全部真实求值，排序、建立种群和archive，预算已用100。
2. 每轮计算状态、生成36候选，在当前archive上拟合五成员ridge，预测均值和离散程度，综合距离、算子先验及启用时的residual修正选短名单。anchor另产生两个候选。池评分与短名单比较是两次排名，不是一次排名结果直接复用。
3. NFE100至210：每轮真实评估两个anchor提案，共55轮、110次评估。当前仍计算pool/proxy，但不让它们决定付费点。
4. NFE210至300：共45轮。保留第一anchor提案；第二anchor与池短名单重新打分并经过门控，决定第二个付费点。默认最多45个真正替换第二槽位的机会，仅占总300次评估的15%，不是90个portfolio点。
5. 每轮只把两个最终选定点的真值加入archive，更新成功记忆，合并后保留最好的100个种群点；archive超过256时拼接最好的100点与最近128点，可能重复。
6. 返回真实观察到的最优点及收敛轨迹。每个新任务重新初始化archive和proxy；保留第一anchor槽位不等于保持独立anchor-only的后续搜索轨迹。

CEC/HPO路径跳过residual，UAV启用；普通BBOB还有特定评分修正。任务名称会影响实际执行规则，论文必须披露。

## 4. 已确认问题与尚待验证的影响

| 发现 | 源码事实 | 影响边界 |
|---|---|---|
| 入口不统一 | `run_roopf.py:130`直接构造仍含锁的类；`roopf/supplement.py:26`显式移除锁；运行构造探针确认为true/false | 本轮full消融、外部比较、UAV、机制和重训评测均走移除锁的入口；不能用旧默认命令替代最终协议 |
| 默认veto不生效 | `model.py:1744`要求计数>=8，`:1857`附近的更新需要默认未启用的额外开关；构造探针确认开关集合为空 | residual仍影响分数/rescue，不能称整个residual关闭；激活veto是否提升效果未知 |
| trust参考点可能滞后 | `model.py:1287`取archive首点，archive只在裁剪时重排 | 应与真实argmin进行独立对照；不能预设改后一定更好 |
| 分数尺度不统一 | `model.py:1328`附近把原目标单位的mu/sigma和无量纲距离/先验直接相加 | 正比例缩放目标可能改变相对权重；需要尺度对照，尚未测得其性能贡献 |
| residual标签与决策不一致 | 默认标签是候选优于incumbent；`:630`的已有`beat_baseline`标签比较两个anchor中的最好值 | 直接改成已有`beat_baseline`也不精确等于替换第二anchor；若研究替换优势，应按实际竞争点构造成对标签，并另外检查长期效应 |
| 受控重训损失的参照系不一致 | `reconstruct_anchor_training.py:20`分别标准化初始父代和200个候选，再比较各自最小z值 | [10,20,30]、[100,101,102]、[0,1,2]都标准化为[-1,0,1]；该质量项不能直接识别整组目标平移改善。此反例已用当前公式核验，但不能据此断定原10-D权重失利的训练原因 |
| anchor输入尺度敏感线索 | `anchor_backbone.py:65`直接对原始适应度softmax；坐标进入含偏置线性网络 | 值得检验目标尺度、坐标平移/旋转敏感性；不能仅据结构断言注意力方向错误或确定因果 |

## 6. 建议的修改研究顺序（尚未执行）

1. 先统一明确的最终配置入口及运行清单；对固定输入做等价检查，保证没有改变最终方法轨迹。
2. 建立单因素开发对照：archive最优点、计数更新、评分尺度分别测试，避免合并修改后无法归因。它们解决实现/定义问题，不保证达到论文性能。
3. 改善学习目标：anchor使用共同参照尺度衡量真实下降或预算内收益；residual使用实际竞争anchor的配对优势，不能仅换一个现成标签名。新权重单独保存。
4. 与强anchor、无门控、简化均匀算子先验对照。确认增益来自门控，还是更强候选/anchor。随机初始化的辅助网络是否必要也要单独检验。
5. 只有开发结果稳定后，再冻结候选、使用预留实例/任务验证；若声称训练改进稳健，需要多个训练种子。当前已查看的外部结果保留作已知开发证据，不继续充当新方案的未见测试。

“更好的最终值”“门控独立价值”“校准”“跨任务泛化”需要分别设验收指标。任何单项进步都不能自动推出普遍领先或不退化保证。
