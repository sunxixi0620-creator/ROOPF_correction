## 2. 源码审计改变了研究问题

### 2.1 离线部分并不是目标函数回归器

原始模型包括固定 anchor policy、固定 residual selector、在线 RidgeFeatureEnsemble、6 类运行时算子（每类6个候选），每轮最多真实评估2个候选。离线选择器输出候选偏好概率，并非可与在线预测均值直接相减的目标值预测；因此不能直接套用此前讨论的两个回归代理残差融合公式。

在线代理是带随机 Fourier 特征的岭回归集成，sigma 混合成员分歧与距离项，并非经过校准的概率置信区间。

### 2.2 原版实际上很晚才开放候选组合

默认 NFE=300、初始种群=100。remaining>0.30 时，最终真实评估全部使用 anchor 候选；因此从100到210 NFE之前，尽管计算了候选池和在线分数，候选池不能被最终采纳。后期仍固定保留一个 anchor 槽位，并通过严格门控决定另一个槽位。

可研究的具体瓶颈：固定的210 NFE开放时机是否错失早期机会？如何通过少量可计费的证据决定何时开放，而不破坏 anchor 的可靠性？

### 2.3 安全门控计数缺口

默认 residual_safety_gate 会读取 portfolio_seen 和 portfolio_best_count，但原版更新这些计数的条件仅包含 aggressive_takeover、admitted_no_best_lock、adaptive_proxy_disable；默认配置不含这三者。由此默认配置下依赖足够候选证据的 residual_blocks 分支无法按原意触发。

新增 model_improved.py 仅在计数更新条件加入 residual_safety_gate；原版不改。这个修改属于逻辑修正，不能单独包装成科研创新，也不能预设修复必然改善适应度。

### 2.4 候选池教师日志不能作为免费观察

`_record_pool_candidate_samples` 会对整个候选池调用 calfitness，但不增加 optimizer.evalnum。默认日志关闭，故不据此认定原版默认结果超预算。正式实验禁用 log_pool_candidates；仅记录已经付费评估的候选。独立 CountedProblem 统计实际每轨迹评估数，并与报告值核对。

## 3. 当前已实现的先导版本

|版本|实现|目的|
|---|---|---|
|baseline|原始 model.py|保持可复现基线|
|counter_fix|独立 model_improved.py，修正计数|隔离逻辑修复影响|
|early_gate|计数修正；在140、160、180、200 NFE提前允许原有安全选择|判断固定开放时机是否值得研究|

early_gate 仍保留第一 anchor 槽位及原有安全门控。它并不强制评估候选池点，也不是已实现的信息增益或自适应主动验证算法。阈值是预先定义的试探配置，不来自先导结果调参。

运行入口 scripts/run_diagnostic.py：BBOB f1/f8/f15 × 3 seeds × 3 variants = 27轨迹，单轨迹300 NFE。每个函数和种子重置模型初始化与随机源，核验初始种群哈希相同；后续轨迹会分化，不声称后续随机流完全一致。

输出 summary.csv、每次真实候选记录CSV、每轨迹npy、代码/模型哈希和环境metadata。输出目录必须不存在，避免覆盖既有结果。成功结束生成 COMPLETE。

## 4. 拟研究的核心算法：证据驱动的保护性候选开放

研究假设：在有限真实预算下，依据在线代理的预测可靠性、候选排序分歧和已付费的候选结果，动态开放第二评估槽位，可以比固定时机开放获得更好的质量/风险权衡。

### 阶段A：测量与校准

1. 为每次选中候选记录评估前 mu、sigma、原始排序、离线 selector 概率、候选来源、remaining、stagnation；得到真实值后再记录误差和是否改善。现有日志对 anchor 某些槽位预测缺失，下一步需补齐付费点的预测，不新增目标查询。
2. 按轨迹维护过去预测误差的滑动/指数加权统计，最少证据数不足时保持保守配置。只能用先预测、后观察的误差，禁止训练内误差冒充泛化误差。
3. 对离线 selector 使用排序或成功事件可靠性分析，不把概率与目标值直接相减。二者的比较转为共享候选池上的排序差异。
4. 日志观测本身需要无扰动测试：固定种子下开关安全日志应保持决策轨迹一致，额外推理时间单独记录。

### 阶段B：受限主动验证（尚未实现）

1. 保留一个 anchor 槽位；另一个槽位可选择 anchor 或候选池候选。
2. 候选池先按在线优化潜力筛选前k个，再考虑与离线偏好明显冲突的点，避免只追求最大分歧。
3. 触发条件只使用已经观察的停滞、校准误差、排序冲突和剩余预算，不使用函数ID或真实最优值。
4. 诊断性候选替代原有第二槽位，不额外增加评估；探索上限按初始种群之后的200 NFE计算。例如5%即最多10次，作为开发超参数而非效果承诺。
5. 后期停止纯诊断，把剩余预算用于已有证据支持的候选。候选验证后更新成功率/校准与开放频率。
6. 不宣称单次评估能知道未选候选的反事实真实结果；只把观察作为当前策略下的证据。需要随机探索概率和倾向概率日志时单独设计，不能从有偏采样直接推断所有算子的真实优劣。

### 阶段C：决策价值近似（B阶段有效后）

有限候选池内模拟可能观测并重新排序，估计一次验证改变未来选择的程度。与简单排序分歧、随机探索、固定时机开放比较。计算成本和sigma校准都必须纳入评估；不能把模拟信息增益当作真实改进。

### 阶段D：MCP 与 Agent

将 archive summary、预测、排序冲突诊断、候选建议、真实评估封装为工具。唯一真实评估入口强制预算校验，LLM 不允许绕过。先比较本地直接调用与MCP同一确定性策略，核验一致性和延迟；然后再比较规则控制、轻量策略与LLM控制。LLM 只在事件触发时建议允许范围内的动作，数值候选由优化模块产生。历史记忆仅来自训练/开发任务，测试结果不写回可检索训练库。

## 5. 实验阶段与通过标准

### P0 环境和复现

已完成安装检查和两组冒烟测试。27轨迹先导运行完后检查 actual_nfe=reported_nfe=300、有限数值、历史最优单调不增、每条轨迹200条付费候选记录。必要时按纸面协议运行24 BBOB+6 CEC-style、每函数100轨迹的原版复现；不把单轨迹冒烟结果与参考表均值直接比较。

### P1 机制诊断

固定原版/计数修正/early_gate三组。测量候选池获准次数、改善次数、首次获准NFE、目标值随NFE变化、GPU同步后的墙钟时间。验证early_gate确实改变决策；若多数任务未获准，说明仅提前运行旧门控不足，不据此否定主动验证整体假设。

### P2 开发与参数锁定

初步开发函数建议BBOB {1,2,6,8,10,15,20,24}；验证集 {3,7,12,17}；其余 {4,5,9,11,13,14,16,18,19,21,22,23} 作为未参与调参的固定实例测试集。种子开发20260630..20260639，验证20260730..20260739，测试20260830..20260859。

这只是当前固定实例的实验划分，不能证明按函数族或任务分布泛化。checkpoint缺少完整训练轨迹，必须核对生成训练函数来源才能声称未见分布；后续引入独立偏移/旋转实例和按函数族留出验证。CEC-style仅为补充迁移测试，不能称为官方CEC竞赛套件。

每次只改变一个机制；开发目标以跨函数排名/标准化log-regret为主，不能混合直接平均不同尺度原始目标值。参数锁定后将配置与哈希存档，测试集不再反馈调参。

### P3 正式比较

- 两条基线必须同时报告：发布原版、计数修正版。
- 消融：只改开放时机、只做可靠性门控、只做分歧验证、完整方法；附等预算随机验证和不使用离线selector的候选排序对照。禁用selector要显式关闭调用，不能仅设置router_weight=0，因为原码会回退到0.004。
- 相关外部基线：标准BO及适用的迁移/代理辅助方法，在实现与预算一致后加入；当前不声称已运行。
- 主预算300（包含100初始样本）。后续500/1000预算敏感性应使用按比例定义的开放时机；当前硬编码early_gate只支持300。
- 至少30配对独立种子，必要时恢复论文100轨迹协议；不事后根据显著性选择停止。
- 主指标：终点simple regret（最优值已知且确认时）、对数regret曲线面积；最优值未知时报告best observed及明确的归一化参照，不混称regret。
- 次指标：达到预设目标的NFE及未达到比例、跨任务胜平负、墙钟时间、候选开放/成功率、尾部退化与失败率。
- 单函数配对差异区间；跨函数作为任务单位做汇总与配对检验，多重比较校正。不可把同一个函数的所有种子当成独立任务重复计数。
- 合成BBOB测试衡量样本效率；真实昂贵目标另加实测总时间。人为sleep只能作为成本敏感性模拟，不能冒充工程收益。

### 继续/回退判据

先导用于诊断，不凭3种子宣称显著。若开放增加且改善次数/终点表现支持假设，再推进主动验证。若只有计数修正有效，则如实报告修复收益。若收益仅发生在开发函数或新增开销抵消收益，回退复杂模块。正式期可预先设定目标如达到同等质量节省20% NFE，但这是工程目标而非预测。
