# ROOPF-Agentic：预算感知自动多智能体元黑盒优化计划

## 1. 研究定位

本分支不把现有 ROOPF 模块简单改名为智能体，而是研究固定真实函数评价预算下，
多种搜索策略如何根据任务反馈自动调整协作关系。原始 ROOPF 保持为不可修改的基线，
新增机制必须在相同 NFE 下通过配对实验验证。

当前实现首先落地 P4b：每个搜索算子作为独立候选生成智能体，探索、开发、恢复和安全
四个决策智能体根据当前预算阶段、停滞程度与已观察收益，对候选生成智能体进行动态调度。
控制器只调整廉价候选池的先验权重，不调用真实目标函数。

## 2. 与原始 ROOPF 的连接点

原始流程：

1. 离线 anchor 生成最多两个基线候选；
2. 六个运行时算子各生成六个候选；
3. 在线代理模型评估 36 个候选；
4. residual selector 与 protected selector 决定真实评价候选；
5. 每轮最多消耗两个真实函数评价。

新增控制层位于步骤 2 与步骤 3 之间。它不会修改 anchor、在线代理模型或最终安全选择器，
因此关闭 `--agentic-mode` 时必须保持复现包行为不变。

## 3. P4b 控制器

六个候选生成智能体：

- `amortized_elite`：离线学习的精英生成策略；
- `current_to_pbest_archive`：差分式开发；
- `covariance_elite`：协方差方向搜索；
- `trust_region`：局部可信域开发；
- `coordinate_pattern`：坐标方向局部搜索；
- `opposition_restart`：全局恢复与重启。

四个决策智能体：

- 探索智能体：预算充足时提高协方差与重启策略的权重；
- 开发智能体：预算后期提高 p-best、可信域和坐标搜索权重；
- 恢复智能体：停滞时提高恢复型算子权重；
- 安全智能体：已有充分失败证据时压低无效算子，但不完全删除。

预算协调器融合四类意见，同时结合每个算子的入选率、最优值改进率与采样不确定性。
输出仅作为在线代理 acquisition 中的先验，不绕过 protected selector。

## 4. 不能提前宣称的内容

当前版本属于确定性 P4b 控制机制，而不是 LLM-based MAS，也不是 P4c 自进化系统。
只有在加入跨任务持久写回并证明其对后续未见任务有益后，才能使用“自进化”表述。
如果后续引入 LLM，建议只让 LLM 输出经过 JSON Schema 验证的低频配置建议，并由安全控制器
限制其范围；不得让 LLM 直接调用真实目标函数或改变 NFE 计数。

## 5. 分阶段实验

### 阶段 A：协议与基线锁定

- 运行安装验证和原始 quick smoke test；
- 对默认 `agentic-mode=off` 与复现包进行结果一致性检查；
- 确认每条轨迹严格消耗 300 NFE。

### 阶段 B：P4b 早期门控

先在较小但覆盖不同地形的函数集上进行配对种子实验：

- BBOB：f1、f5、f8、f10、f15、f20、f24；
- CEC-style：仅作为补充诊断，不作为早期唯一结论；
- 每个函数至少 10 个配对种子；
- 比较最终最优值、regret AUC、运行时间和算子利用率。

进入全量实验的门槛：不能只依靠单个函数获胜，且任何明显退化都必须定位到具体决策阶段。

### 阶段 C：P4a+P4b

如果 P4b 有稳定收益，再从训练函数学习四个决策智能体的融合权重和安全阈值。
训练函数与最终测试函数严格隔离。P4a 只提供初始化先验，P4b 仍根据当前任务反馈适应。

### 阶段 D：受控 P4c

最后再研究跨任务写回。只保存经过独立验证的算子统计或策略版本，并提供回滚、版本号与
污染检测。P4c 必须与“仅当前任务适应”的 P4b 分开报告。

## 6. 必需消融

- 原始 ROOPF；
- ROOPF + 原有 `success_logits`；
- 固定多策略混合，不使用反馈；
- 仅探索/开发阶段调度；
- 去掉安全智能体；
- 完整 P4b；
- 后续的单 LLM、LLM-MAS 与蒸馏控制器版本。

## 7. 论文可主张的创新边界

只有在相同 NFE 下，完整方法对未见函数获得稳定收益，并通过上述消融证明收益来自动态协作
而不是额外预算时，才建议将其表述为“预算感知的自动多智能体 MetaBBO”。在此之前应使用
“实验性 P4b 控制层”这一保守名称。
